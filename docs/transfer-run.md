# Пространственный перелёт к Mun: итерация 3

Этот сценарий выполняет импульс ухода с орбиты Kerbin и проверяет последующую
траекторию по patched conics KSP. Вход в SOI, торможение у Mun и посадка
относятся к следующим итерациям. Успех здесь называется `transfer_ready`,
а не «захват» или «посадка».

## Запуск из корня проекта

Требуются зависимости из `requirements.txt`, игра SLIM с установленным
kRPC 0.5.4 на портах 5000/5001 и снимок `SLIM_Transfer_Start_v1` в игровой
папке `saves/SLIM`. Его проектная копия находится в `saves/`.

```powershell
# Подбор на паузе. Автоматически загружается фиксированный снимок Kerbin.
.\.venv\Scripts\python.exe transfer.py --plan docs\experiments\my-spatial-plan.json

# Выполнение из того же исходного снимка; оба результата должны иметь новые имена.
.\.venv\Scripts\python.exe transfer.py --execute docs\experiments\my-spatial-plan.json --result docs\experiments\my-transfer-result.json

# Проверки без полёта.
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
```

Оба режима загружают исходное сохранение и поэтому заменяют активную сцену
KSP. Существующие файлы результатов не перезаписываются. Режим подбора
не включает двигатели и оставляет игру на паузе; созданные им узлы удаляются.
После успешного выполнения создаётся уникальное `SLIM_Transfer_Ready_<UTC>`.
Игру нужно оставить на паузе до готовности управления следующей итерацией.

## Расчёт и проверка траектории

Для моментов ухода в пределах примерно трёх начальных оборотов и длительностей
перелёта 20000–40000 с берутся будущие позиции из `Orbit.position_at` KSP в
общей невращающейся системе Kerbin. Начальная скорость оценивается центральной
разностью положений с шагом 1 с. Решается нулеоборотная пространственная задача
Ламберта: обе дуги, ограниченная бисекция универсальной переменной, до 100 шагов.
Это расчёт граничной задачи манёвра, не самостоятельное интегрирование движения.

Использованы уравнения f/g и универсального времени из
[официального описания poliastro](https://docs.poliastro.space/en/stable/autoapi/poliastro/core/iod/index.html).
Библиотека poliastro не устанавливается и её код не копируется. Реализация
проверяется по опубликованному там примеру Curtis 5.2 и круговым траекториям.

Для предварительного пролёта задаётся боковое смещение относительно Mun
с оценкой гравитационной фокусировки. Дешёвые кандидаты переводятся в
компоненты реального узла через `node.orbital_reference_frame` kRPC:
там x направлена антирадиально, y проградно, z нормально. Поэтому радиальная
компонента узла имеет знак, противоположный компоненте x.

Далее проверяется именно `node.orbit.next_orbit`: в последовательности будущих
патчей должна присутствовать Mun. Локальные поправки компонент узла вычисляются
по численным производным прогнозируемого перицентра KSP. Рабочая цель пролёта
50 км, допустимый коридор передачи — 30–80 км над условной сферой Mun.
Это безопасный пролёт для последующей отработки захвата, а не конечная
целевая орбита 15 × 25 км. Ранжирование учитывает ориентировочную стоимость
захвата и топливный бюджет; расход проверяется по доступному центральному баку.

## Выполнение и критерий результата

Выполняется только импульс по проверенному узлу. Центрирование по половине
расчётной длительности остаётся приближением конечного импульса. Ускорение
времени используется только без тяги до начала импульса. Перед ним остаётся
не менее 60 с обычного времени для стабилизации. Газ разрешается при ошибке
направления ≤1° для начала и ≤3° во время горения. Ошибка измеряется скалярным
произведением реального направления аппарата и оставшегося вектора импульса.

Газ плавно уменьшается с остаточным Δv. При остатке ≤0,15 м/с двигатель
выключается, ожидается физическое обновление и проверяется отсутствие тяги.
После этого проверяется прогноз из ФАКТИЧЕСКОЙ орбиты аппарата, а не узла.
Если перицентр вышел за коридор, допускается одна автоматически рассчитанная
коррекция ≤20 м/с, также с ограниченным выполнением. Повторное отсутствие
приемлемого прогнозируемого пролёта считается ошибкой.

Пределы: 120 реальных секунд на подбор, 900 с на весь управляемый участок,
10 итераций локальной коррекции, минимум 433 кг в центральном баке, 55 деталей,
доступная тяга, неизменный аппарат и тело. Контролируются остановка/откат UT,
ошибка телеметрии и пропуск окна. При завершении или исключении предпринимаются
нулевой газ, выключение ускорения, пауза, отключение AP, удаление собственных
узлов и закрытие журнала. Отказ канала kRPC может помешать выполнению команд
очистки; таймер не прерывает отдельно зависший RPC-вызов.

CSV и начальные параметры записываются в `logs/`. JSON выполнения содержит
путь к CSV, конечные параметры, прогноз Mun из фактической орбиты, сведения
о коррекции и SHA256 расчётного кода с нормализацией переводов строк в LF.
Подтверждение реального входа в SOI и работы захвата требует следующей итерации.
